# Research notes (a small memory so the same question is not searched twice)

Keep notes in the PROJECT, not in this skill: `docs/design-notes/<topic>.md` (one topic per file, under 40 lines). Before researching, run `ls docs/design-notes` and read a note whose name matches. Write a note only when you actually researched something that the next agent could reuse.

Format:

```
# <topic, e.g. "variable fonts for the headline">
Date: 2026-10-25     Status: verified | partly verified | not verified
Question: <one line>
Answer: <3 to 8 lines, with the concrete value or rule>
Sources: <URL> (<what it said>), <URL>
Licence/risk: <for fonts, images, code: the licence, or "unknown">
Applies to: <this project / any project>
```

Rules: a note is a claim with a source, not an opinion. If a source is a blog or an AI-written page, say so and mark "partly verified". Notes older than a year, or about a browser feature, should be re-checked before relying on them. Never put secrets, customer data or private URLs in a note.
